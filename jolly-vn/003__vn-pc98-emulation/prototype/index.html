GETTING CHAPTER 2 INTO THE GAME

Hot swap (no reboot): save the generated floppy, then in the emulator's own disk UI mount it in FDD2 (the second floppy row's Insert button), and press Enter in the game. Chapter 1 ends with [load file="B:/CH02-….NOV"], which the engine resolves from drive B: — verified working in this build.

Reboot: open the generated reboot link. It reloads the emulator with a hard disk whose start.novel is Chapter 2, so it boots straight into the new chapter.

Disk contract: one NovelML file per chapter, 8.3 DOS names (CH02-RIN.NOV), clean backgrounds plus a separate sprite — the engine draws all UI.

IF IT SEEMS STUCK ON A BLACK SCREEN

Boot is slow (one to three minutes) and the screen stays black while the first background is decoded. The boot floppy automatically retries the engine launch, and the engine re-reads any file that fails its integrity checks, so a black screen usually resolves by itself — wait before reloading. If the DOS prompt (C:\>) ever appears, type SUIKA-98.EXE -4 and press Enter to relaunch the game by hand. Full detail is in README-EMULATION.md.

RUN LOG

Real-emulation build for 003__vn-game-design/PROTOTYPE.md. Emulator: self-hosted WebNP2 (Neko Project II kai, WASM) in player/; the emulator core is unmodified upstream (only disk/clock URL plumbing in the shell). Guest: SUIKA-98.EXE, a Suika3 engine compiled from upstream source with small documented reliability patches for flaky emulated disk reads (see README-EMULATION.md), running under a DOS/32A extender on real FAT images in disks-real/ built by tools/build_disk.py. ROM-less boot uses NP2kai's built-in BIOS-compatible routine and the bundled FreeDOS(98) floppy; no BIOS or font ROMs are distributed. The previous JavaScript imitation is kept as legacy-renderer.html only so the difference is visible.
